- S01 (2026-08-19): until the `.venv` hidden-flag defect is resolved in E01, run direct module commands as `PYTHONPATH=src python -m macropulse.smoke` (pytest unaffected via `pythonpath` ini).

Source codes carry explicit verification status; 7 references remain `unverified` (2 are TBD-S05 placeholders) and must be confirmed live before production use. The `vintage-transparency` module has no standalone indicators - it is realized via provenance fields and the S07 release calendar.
- S03 (2026-08-19): PostgreSQL 16 schema locked via `src/macropulse/db/models.py` + migration `bcc78be651f0`; vocabularies (evidence labels, frequencies, source systems, verification statuses) are imported from scope/catalog so schema cannot drift. Missingness governance is schema-enforced (CHECK value NULL requires missing_reason). Observation identity = (indicator, country, period, vintage, source). API response shapes pinned in `src/macropulse/api/schemas.py` with `extra="forbid"`; S13 implements them unchanged. Cloud constraints (DATABASE_URL only, provider pooler via URL params, no local-only extensions) recorded in `docs/DatabaseContract.md` for the Vercel target.
- (2026-08-19, student): Database is PostgreSQL everywhere - local (Docker) and cloud. Final target deployment is Vercel, which favors managed PostgreSQL (e.g., Vercel Postgres/Neon-class providers); exact provider chosen in C02. No SQLite fallback: S03 waits for Docker.
- S04 (2026-08-19): Connectors write raw observations only (S03 data flow); FRED connector has two modes sharing one parser - live (`real` label) and deterministic no-key fixture (`mocked` label). FRED `"."` values map to explicit `fred_missing_value` missingness. `release_time` = `retrieval_time` for FRED plain fetches (documented limitation; ALFRED realtime queries deferred to S07). Live-mode tests use httpx.MockTransport; no live API call has been made yet.
- S05 (2026-08-19): World Bank + ILOSTAT connectors live-verified - first `real`-labelled retrievals. Catalog corrections: digital payments = WB `g20.any`; ILOSTAT youth unemployment = `DF_SDG_0852_SEX_AGE_RT` (S02's SDG_0811 guess was wrong - SDG 8.1.1 is GDP growth); ILOSTAT NEET = `DF_EIP_NEET_SEX_RT`. ILOSTAT annual rows are selected via the FREQ dimension (mixed-frequency dataflows). Reproducible live audit: `PYTHONPATH=src python scripts/audit_sources.py` (14/14 OK). Only FRED `CLVMNACSCAB1GQ` remains unverified (needs FRED key).
- S05 follow-up (2026-08-19): FRED API key configured in gitignored `.env.local`; all four FRED catalog codes live-verified. `CLVMNACSCAB1GQ` was invalid (HTTP 400) - corrected to `CLVMNACSCAB1GQDE` (Real GDP Germany, quarterly SA, 142 points live). Catalog now has zero unverified codes; audit script probes FRED when a key is present and self-loads `.env.local`.
- S06 (2026-08-19): Normalization is a pure deterministic function (`normalize_series()`), separate from persistence (`persist_normalized()`). Units are canonical from the catalog and values are NEVER converted at this layer - any unit transformation is a labelled derived metric (S08). Frequency inferred from median month-gap (tolerates one missing period; irregular spacing is an error, not a guess). Seasonal adjustment is caller-overridable per series because FRED/WB differ (SA vs NSA CPI); the applied value is stored per observation. Fixed in-unit: WB/ILOSTAT connectors were stamping `vintage=period`, contradicting the documented snapshot semantics - both now stamp `vintage=retrieval date`, so observation identity changes on each refetch and revisions stay visible (RQ4). `release_time=retrieval_time` remains a documented proxy until S07.
- S07 (2026-08-29): Quality grades form a closed vocabulary imported from the S03 API contract (single source of truth); priority is flagged > ungraded > revised > official, and `preliminary`/`estimated` are RESERVED - never emitted because no source exposes release-stage metadata (emitting them would be fabrication). Flags are INSERT-only (audit trail); grades are UPDATE (judgement). Revision semantics: a revision is a new (period, vintage) row, never an update; `relative` deltas are None on zero bases or value<->missing transitions. ALFRED realtime queries are live-only (no silent mocks for vintage data), which required rekeying the S06 duplicate check from period to (period, vintage) so vintage chains can normalize and persist. `release_calendar` stays unpopulated - no API exposes scheduled-release timestamps; a future populated calendar must be sourced, not fabricated.
